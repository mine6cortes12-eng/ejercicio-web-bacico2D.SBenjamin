Un buen diseño

Es el mapa completo del sistema que define lo que se construye, cómo se conecta y con qué tecnologías, garantizando que sea robusto, seguro y escalable desde el principio.

Principios de buen diseño - SOLID S Single Responsibility Principle-Cada módulo hace una sola cosa. O Open/Closed Principle-Abierto para extender, cerrado para modificar. L Liskov Substitution Principle-Las subclases deben poder reemplazar a las padre. I Interface Segregation Principle-Las subclases deben poder reemplazar a las padre. D Dependency Inversion Principle-Depender de abstracciones, no de implementaciones

Patrones de Diseño más usados Creacionales — cómo se crean los objetos. Estructurales — cómo se organizan los componentes. De comportamiento — cómo se comunican los componentes.

Otros principio DRY: Don't Repeat Yourself-no duplicar código. KISS: Keep It Simple—mantenerlo simple. YAGNI: You Aren't Gonna Need It—no construir lo que no se necesita. SoC: Separation of Concerns—separar responsabilidades

Evolución resumida

  • 2010s → Microservicios, Docker, Cloud.
